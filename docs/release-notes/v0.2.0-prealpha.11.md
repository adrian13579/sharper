# v0.2.0-prealpha.11

Adds a colored interactive `sharper setup` wizard for language selection, existing-server discovery, confirmed installation of pinned server tools into a user tools directory, and confirmed agent registration. Roslyn uses dotnet tool-path installation; TypeScript/ESLint use npm via Node with exact direct versions, a private manifest/lockfile and disabled install scripts. Target project dependencies and native rule configuration are not changed.

CLI behavior change: no-argument terminal launches open the wizard; redirected launches retain MCP behavior. Explicit `sharper mcp` remains protocol-only and existing direct `setup <client>` commands remain available. Colors respect redirection, NO_COLOR, TERM=dumb and --no-color. Invalid choices reprompt; cancellation and unresolved failures have explicit outcomes. Installer subprocesses have bounded deadlines and cancellation; the wizard detects missing SDK/Node prerequisites and reports installation guidance.

Discovery shares the runtime server resolver without starting an LSP session. Detection does not certify project loading or successful analysis. No registry publication, release tag or Stryker run is performed by this change.

Local Windows validation: all 210 .NET tests pass with zero skips, including 14 wizard/discovery regressions, 41 existing CLI checks and actual Roslyn/TypeScript/ESLint integration. A subsequent focused 55-test run passes after final help/prerequisite wording changes. Real guided setup installed all three pinned servers into an isolated tools directory, retained TypeScript when adding ESLint, and configured a disposable Claude profile. The full real-server suite used the Roslyn installation produced by that wizard. Terminal launch and prompt cancellation were exercised separately. Analysis coverage is 96.2% line / 87.7% branch; the shared discovery entry point is fully covered. CLI subprocess coverage is excluded.

Windows Native AOT packing passes without trim/AOT warnings. Installed NuGet and offline npm packages pass the guided setup registration check, direct client setup, repeated actual Codex registration and real Roslyn/TypeScript/ESLint diagnostic/navigation checks. These native MCP checks use all three servers installed by the real wizard run, with fixture project dependencies kept separate. Linux execution and complete two-platform npm assembly remain CI checks. Stryker remains stopped.
